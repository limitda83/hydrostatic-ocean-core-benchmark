# 38. E17 — 폐쇄의 자료 발자국을 호스트 너머로 넘기는 비용 (실험 기록)

**날짜:** 2026-09-15 (1회차) → 같은 날 **2회차 재측정**(docs/90 **N44**: 1회차의 케이스 D·E 폐기)
**실험:** `expr/E17_module_boundary` **도구:** `libs/cuda/src/module_boundary.cu` · `tools/module_boundary.sh` ·
`tools/module_boundary_report.py` **노드:** `gpgpu` RTX 5090 (PCIe 5.0 ×16) · `ktcloud` H100 (PCIe 5.0 ×16, 호스트 공유)
**질문:** v0.6 TKE 폐쇄가 스텝마다 읽고 쓰는 배열을 **호스트를 거쳐** 다른 장치로 넘기고 돌려받는 시간은,
같은 장치·같은 격자·같은 정밀도에서 그 폐쇄를 제자리에서 계산하는 시간의 몇 배인가.

---

## 1. 무엇을 쟀는가

**자료 발자국** — `libs/core/closure.py::tke_step` 의 서명과 `cfd_exp3d5_cuda.cu::k_closure` 가 읽는 배열을
대조해 확정(추정 아님). 스텝마다 오가는 것: 입력 `u,v,b`(셀 nz) + `e,K_m_old,K_h_old`(계면 nz+1) = 183 값/열,
출력 `e_new,K_m,K_h` = 93 값/열 → **276 값/열**. 정적 배열(`dz3,mask3,dz3u,dz3v,masku,maskv`, 180 값/열)은
한 번만 올리는 것으로 보고 따로 잰다.

**두 케이스** — B: 호스트 모델이 장치에, 모듈이 호스트 쪽(D2H 입력 + H2D 출력). C: 호스트 모델이 CPU 에,
모듈이 장치(H2D 입력 + D2H 출력). 각각 고정(pinned)·페이지가능 메모리. CUDA 이벤트, 5회 반복, median+MAD,
매 표본 뒤 device synchronize.

**분모** — docs/31 §3c 의 `fb` 분해에서 `.tke` − `.v05`(같은 장치·격자·정밀도·스킴·CFL·스텝수). 결합 도구는
차이가 두 MAD 의 합의 2배를 넘지 않으면 그 칸을 **폐기**로 표시한다(이번 자료에서는 해당 없음, 최대 ±0.01 ms).

**읽는 법.** 학습 모듈이 실제로 쓸 정밀도(fp32)에서, 400² 이상, 두 카드 모두 — **호스트를 거치는 왕복이
폐쇄 자체의 2.1~2.6배**다. 이 값은 모듈의 연산을 0 으로 놓은 **하한**이다(호스트 왕복은 어떤 구현도
피할 수 없는 비용이므로). 유일한 예외 RTX 5090 fp64(0.4×)는 경계가 싸서가 아니라 그 구성의 폐쇄가
H100 의 6.7배로 느린 것이다.

**왜 정밀도가 격자보다 세게 작용하는가.** 왕복은 바이트에 비례해 fp32 에서 절반, 폐쇄 계산은 연산에
비례해 5090 에서 12.9배가 준다. 격자를 100배 키워도 비는 거의 변하지 않는다(둘 다 셀 수에 선형).

**장치 상주 모듈의 경계 비용은 이 실험이 재지 않는다.** 제자리에서 배열을 읽는 모듈은 복사를 하지 않으므로
그 비용은 0 이고, 잴 것이 없다. 모듈이 자기 레이아웃의 버퍼를 요구하는 경우(외부 프레임워크)의 복사 비용은
그 프레임워크에 달린 것이라 이 실험의 범위 밖이다.

## 4. 폐기한 것 (1회차, docs/90 N44)

1회차 도구에는 두 케이스가 더 있었고, 외부 검토에서 둘 다 잰 것과 주장한 것이 다르다는 지적을 받았다.
- **D "장치 내 복사"** — 발자국을 두 번째 장치 버퍼로 복사하는 시간을 재고 "장치 상주가 치르는 경계"라 불렀다.
  제자리 읽기 모듈은 복사하지 않으므로 이것은 실재하지 않는 비용이다. 그 위에 세운 "0.08~0.18×, 경계 하나가
  14~26배" 는 근거가 없어 **삭제**.
- **E "두 스트림 중첩"** — 겹칠 연산 없이 D2H 하나를 두 스트림으로 쪼갰을 뿐. "중첩으로 못 숨긴다"는 결론은
  이 측정에서 나올 수 없어 **삭제**.
두 케이스를 도구에서 제거하고 두 노드에서 다시 쟀다. B·C 는 1회차와 0.3 %(5090) · 2.3 %(H100, 공유 호스트)
안에서 일치한다. 1회차 CSV 는 `_DISCARDED_DE` 로 SUPERSEDED 에 남겼다.

같은 검토에서 결합 도구의 결함 셋(장치를 파일명으로 판정, 키에 케이스·솔버·CFL·스텝수 없음, 정적 변종이
키에 없음)을 고쳤다. 출판 수치는 우연히 살아남았고, 도구가 보증한 것이 아니었다.

## 5. 한계

- **하한이다.** 모듈의 연산, 프레임워크 호출 오버헤드, 레이아웃 변환, 두 자원 풀의 스케줄링은 빠져 있다.
- **PCIe 5.0 ×16 에 한정.** NVLink-C2C 처럼 링크가 한 자릿수 빠른 구성은 측정하지 않았고, 거기서는 결론이
  뒤집힐 수 있다.
- `ktcloud` 는 호스트를 공유한다(R7-1). H100 의 C·페이지가능 값은 상한이며, 두 노드의 C 가 3 % 안에서
  일치하는 것과 1·2회차가 2.3 % 안에서 일치하는 것이 오염이 크지 않았다는 근거다.
- 100² 는 두 값 모두 작아 커널 발사·호출 지연이 지배한다. 그 격자의 비는 인용하지 않는다.
