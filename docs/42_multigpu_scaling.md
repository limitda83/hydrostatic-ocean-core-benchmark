# 42. 다중 GPU 강확장 — 노드 안(RTX 5090 ×2·×4)과 노드 간(H100 ×2) — E19 (2026-09-23/24)

**질문:** 같은 문제를 한 노드의 GPU 여러 장에 나눠 실으면 스텝당 시간이 얼마나 줄고, 32 GB 카드에 들어가지 않던 문제가 들어가는가. 동일 정확도(단일 장치와 비트 동일) 조건.

**구현:** `libs/cuda/src/cfd_exp3d5_cuda_multi.cu` — 단일 프로세스·다중 장치, y-슬랩, 깊은 halo H=16 행, 스텝당 1회 pack → `cudaMemcpyPeerAsync` → unpack (docs/03 §12). fb 스킴만. 첫 시도(`cudaMemcpy3DPeer` 스트라이드 복사)는 1000² 에서 스텝당 약 30 ms 의 교환 비용이 나와 폐기.

**게이트 (R2·R4-2):** `tools/e19_gate.sh` — 400²×30, DC·DC+TKE, 50 스텝: 1장·2장·4장(H=8, 16) 상태 파일이 단일 장치 이진의 상태와 **max|diff| = 0** (`expr/E19_multinode_scaling/data/gpgpu_20260924/gate_gpgpu_4card_20260924.txt`; 9/23 의 1·2장 게이트는 `data/SUPERSEDED_gpgpu_20260923/gate_gpgpu_20260923.txt`).

**노드:** gpgpu, RTX 5090 ×4 (장치 1·0·2·3), PCIe(NVLink 없음; `nvidia-smi topo -m` 모든 쌍 `NODE`, `data/gpgpu_20260924/e19_topo_20260924.txt`). **보고 세션은 2026-09-24 10:26~10:40** — 다른 사용자의 GPU 프로세스 없음, 부하 평균 ≈ 1.7(`nvidia_smi_before/after.txt`, `e19_4card_chain.log`), 1·2·4장을 한 세션에서 측정(`DEVSETS="1 1,0 1,0,2,3"`). 9/23 세션(2장까지; GPU 2·3 은 다른 사용자(gsrai) 학습이 점유, 부하 ≈ 17)은 `data/SUPERSEDED_gpgpu_20260923/` 로 격리 — 값은 9/24 와 단일 카드 0.03 % 이내, 2장 0.1~1 % 이내로 같았다(9.58/65.70/31.87/195.86 대 9.58/65.70/31.87/195.92 ms; 2장 6.75/36.87/141.35 대 6.68/36.73/141.19). 그보다 앞선 두 실행은 사용자 자신의 `nawtic` 작업이 GPU 0·1 을 94~96 % 로 쓰는 동안 돌아 **폐기**(`output/e19_*_CONTAMINATED_nawtic_on_gpu01`, 단일 카드가 사다리보다 35 % 느리게 나왔음).

## 2. 읽을 것

1. **용량 경계가 옮겨진다.** 단일 32 GB 카드에서 CUDA 가 OOM 이던 2000²×30 이 두 장에서는 돈다(각 카드 약 절반 + halo). 그 시간은 EPYC 노드 최선 구성보다 DC 4.7배, DC+TKE 7.5배 빠르고, H100 한 장(109.68 / 185.25 ms, docs/32)보다는 1.29배 / 2.18배 느리다. **네 장**은 그 시간을 다시 거의 절반으로(82.49 / 220.97 ms; 2장 대비 1.71 / 1.83) 줄여 EPYC 노드보다 8.1 / 13.7배, DC 에서는 H100 한 장보다 1.33배 빠르다(DC+TKE 는 H100 한 장의 0.84배). 사다리(docs/32)에서 "2000² 에서 CPU 노드가 1.6~5.9배 이긴다" 는 문장은 **카드 한 장**에 대한 것이며, 두 장이면 뒤집힌다.
2. **강확장은 2장이 1000² 에서 1.8배, 400² 에서 1.4배; 4장은 1000² 에서 2.8배(2→4 카드 1.55배), 2000² 에서 2→4 카드 1.7~1.8배, 400² 에서 1.6~1.7배(2→4 카드 1.14~1.24배).** 두 장 모두 같은 종류이고 통신은 스텝당 한 번(halo 16행 × 8~9 배열)이므로 손실의 대부분은 halo 행의 중복 계산(1000²: 32/500 = 6 %)과 스텝당 세 번의 장치 동기화·pack/unpack 커널 발사이다. 400² 는 발사 지배 영역이라 카드를 더해도 이득이 작다(docs/32 §2 와 같은 이유).
3. **드라이버 자체의 비용**은 1장에서 3~15 %(400² 에서 크고 1000² 에서 3~4 %). 2장 가속비는 단일 장치 이진 기준으로 보고한다.
4. **폐쇄를 켜도 확장 효율이 같다**(2장 1.79 대 1.80, 4장 2.77 대 2.81): 폐쇄는 열 단위라 통신을 늘리지 않는다 — docs/41 의 예측대로.
5. **네 장의 효율은 2000² 에서 가장 좋다**(2→4 카드 1.71 / 1.83): 슬랩당 500행에 halo 32행이라 중복 계산이 6 %(이상 가속 두 장 대비 1.9)이고 카드당 스텝이 길어 세 번의 동기화가 묻힌다. 1000² 에서는 슬랩당 250행(중복 13 %, 이상 가속 3.5)에 카드당 스텝 24 ms 로 1.55배, 400² 는 중복 32 %(이상 3.0)에 발사 지배까지 겹쳐 1.14~1.24배. 두 장의 이상 가속은 1000² 1.9, 400² 1.7. 상한과 측정값의 차(400² 최대 0.6, 1000² 0.1~0.7)가 스텝당 세 번의 동기화와 pack·복사·unpack 커널의 몫이며 따로 재지 않았다(외부 감사 2026-09-24 P2).

## 3. 한계

- fb 스킴만. θ·PCG 는 반복마다 halo + 전역 합이 필요하고, 다중격자는 분산 V-사이클이 필요하다(docs/41).
- RTX 5090 은 노드 안·PCIe. 다중 노드는 H100 2노드(§4)만 — 부록 C 의 E11 상수는 노드 안 값이다.
- 노드 안은 4장까지(노드의 전부). 그 이상은 다중 노드.
- (갱신) H100 은 아래 §4 — ktcloud 세션이 "노드 2개 × H100 1장" 이어서 MPI 드라이버로 노드 간 측정.

## 4. 노드 간 — H100 ×2 (ktcloud main1 + sub1, 노드당 H100 1장, Open MPI 4.1.9 / HPC-X, UCX)

**구현:** `libs/cuda/src/cfd_exp3d5_cuda_mpi.cu` — 같은 슬랩·깊은 halo 를 랭크당 GPU 1장으로, halo 는 `MPI_Sendrecv` (기본: 고정 호스트 메모리 스테이징; `--device-mpi`: 장치 포인터를 직접 넘기는 CUDA-aware). 빌드 `make -C libs/cuda mpi ARCH=sm_90`; 실행 `tools/e19_run_mpi.sh` (`mpirun -np 2 -H main1,sub1`). **게이트:** 두 경로·halo 8/16 모두 단일 장치 상태와 max|diff| = 0 — DC 는 `data/ktcloud/gate_mpi_20260923.txt`, DC+TKE 의 CUDA-aware·halo 8 셀은 외부 감사(2026-09-24) 지적으로 추가한 `data/ktcloud/gate_mpi_tke_20260924.txt`; 스윕의 모든 행도 1장 상태와 차 0.

**노드 상태:** 컨테이너 호스트 부하 평균 ≈ 60(공유), GPU 는 각 노드에서 우리 작업만. **재측정 1건:** 9/23 의 DC+TKE 1000² host-staged 실행은 5회 측정·상태 기록을 마친 뒤 rank 1(sub1) 이 종료 단계에서 segfault 했다(`run.log` 22:02:53 항목; 값 36.19 ms, 상태는 1장과 비트 동일). 외부 감사 지적으로 2026-09-24 22:28 에 같은 번들로 재측정(크래시 없음, 29.88 ms, MAD 0.14 %) 하여 CSV 의 그 행을 대체했다; 원래 행은 `run.log` 에만 남는다. 두 값의 차(36.19 대 29.88)는 공유 호스트의 부하가 호스트 스테이징 경로에 미치는 영향의 크기를 보여 주는 것으로, 원고 한계 절에 적었다. 번들 생성기의 O(N²) hypsometry 루프가 이 호스트에서 20분+ → 벡터화(docs/90 N44).

**읽을 것.**
1. **강확장은 노드 간에서도 1000² 1.72배, 2000² 1.85배** — 노드 안 RTX 5090 두 장(1.78·—)과 같은 수준. 폐쇄를 켜도 같다(열 단위).
2. **400² 는 네트워크 지연이 지배**: host-staged 는 한 장보다 느리고(0.79) CUDA-aware 로 겨우 1.22. 카드를 더할 문제 크기의 하한이 노드 간에서는 노드 안보다 높다.
3. **CUDA-aware 가 host-staged 보다 늘 빠르거나 같다** — 이득은 DC 400² 1.5배, DC 2000² 1.19배이고 나머지 네 칸은 0~5 %.
4. **노드 환산:** H100 2노드 = EPYC 노드 7~11개(DC), 13~30개(DC+TKE). 2000² DC+TKE 에서 30배는 EPYC 기준선이 64스레드 최선(3016.88 ms)인 칸이라 비율이 크다.
