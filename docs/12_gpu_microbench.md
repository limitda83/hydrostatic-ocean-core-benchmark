# GPU 마이크로벤치마크 — RTX 5090 roofline 상수 (실측)

노드 `gpgpu` · NVIDIA GeForce RTX 5090 (Blackwell GB202, **cc 12.0 / sm_120**) ·
CUDA 13.2 · CuPy 13.6.0 · 2 GiB 피연산자 · CUDA event 타이밍 · warm-up 5회, 30회 반복
재현: `CUDA_VISIBLE_DEVICES=<free> .venv/bin/python -m tools.gpu_microbench --size-mib 2048`

## 2. **T2에 대한 답 — 48:1이라는 숫자는 우리 워크로드에 오해를 부른다**

roofline의 갈림점(ridge point) = 달성 연산성능 ÷ 달성 대역폭:

| 정밀도 | ridge AI [FLOP/byte] | 의미 |
|---|---:|---|
| float32 | 94430 / 1580 = **59.8** | AI 60 미만이면 대역폭 지배 |
| float64 | 1980 / 1580 = **1.25** | **AI 1.25만 넘으면 연산 지배** |

해양모델 stencil 커널의 산술강도는 대략 `AI ≈ 0.15 ~ 0.5 FLOP/byte` 다
(운동량 갱신: 점당 ~20 FLOP / ~80 byte 이동 ≈ 0.25; PCG의 라플라시안 적용은 더 낮다).
**두 정밀도 모두의 ridge보다 한참 아래** → 우리 커널은 fp64에서도 여전히 대역폭 지배다.

> **결론:** RTX 5090의 FP64가 FP32 대비 48배 느린 것은 사실이지만,
> **이 프로젝트의 커널에는 그 페널티가 적용되지 않는다.**
> fp64 → fp32 전환의 실이득은 **연산비 48배가 아니라 트래픽 절반, 즉 약 2배**다.
> 이것이 문헌 L9·L10의 예측을 이 하드웨어에서 실측으로 확인한 것이다.

### 2.1 데이터센터 GPU와의 대비 (중요)

- H100급은 FP64:FP32가 약 1:2라 **fp64 ridge가 훨씬 높다**(대략 AI 10 부근).
- RTX 5090은 fp64 ridge가 **1.25**로 훨씬 낮다 → **AI 1.25~10 구간의 커널은
  H100에서는 대역폭 지배지만 5090에서는 연산 지배로 뒤바뀐다.**
- 우리 커널은 그 구간 아래에 있어 영향이 없지만, **Phase 2에서 상태방정식(EOS)이나
  난류 폐합처럼 AI가 높은 커널이 들어오면 이 경계를 반드시 다시 확인해야 한다.**
  (해수 상태방정식은 고차 다항식이라 AI가 높다.)

## 3. 운영상 발견 — `gpgpu` 는 공유 노드다

측정 시도 중 **GPU 0·1이 다른 사용자 프로세스에 각각 29.9 GB 점유**되어 있어
1 GiB 할당조차 실패했다 (`OutOfMemoryError`). GPU 2·3만 유휴 상태였다.

```
0, RTX 5090, 29914 MiB / 32607 MiB   <- 사용 중 (타 사용자)
1, RTX 5090, 29890 MiB / 32607 MiB   <- 사용 중 (타 사용자)
2, RTX 5090,    15 MiB / 32607 MiB   <- 유휴
3, RTX 5090,    76 MiB / 32607 MiB   <- 유휴
```

> **벤치 절차에 반영할 것 (R7-7):**
> 1. 측정 전 `nvidia-smi` 로 점유 상태 확인
> 2. `CUDA_VISIBLE_DEVICES=<유휴 GPU>` 로 **명시적 고정**
> 3. 사용 GPU 인덱스와 측정 시점의 타 프로세스 유무를 **manifest에 기록**
> 4. 타 작업과 겹친 run은 폐기
>
> 이를 지키지 않으면 GPU 성능 수치가 조용히 오염된다.
> 특히 GPU 0이 기본값이므로 **아무 설정 없이 돌리면 점유된 GPU에 들어간다.**

## 4. 아직 답하지 않은 것

- **달성 대역폭 1580 GB/s 가 이 칩의 실질 상한인가?** 더 큰 피연산자, 다중 스트림,
  `__ldg`/벡터화 로드로 상한을 다시 확인해야 한다. CuPy elementwise는 상한 측정에
  최적이 아니다 → **CUDA 백엔드(P5)에서 자체 커널로 재측정**한다.
- 실제 stencil 커널의 AI는 손계산이 아니라 **Nsight Compute roofline 으로 확인**한다.
- CPU 쪽 STREAM 상수(`geo85`, `gpgpu` 각각)를 측정해야 CPU roofline이 완성된다.
